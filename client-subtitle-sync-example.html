📖 使用说明

方案1: 音频流本地播放 + 时间戳字幕同步

  • 原理: 客户端直接播放原始音频流，根据 Azure 返回的时间戳 (offset) 同步显示字幕
  • 优点: 延迟低，字幕精确对齐音频时间
  • 缺点: 需要音频流地址可直接访问，可能存在播放器与 Azure 识别的时间偏差

时间戳对齐机制

  1. Azure offset 含义: Azure 返回的 offset 是相对于音频流开始的偏移时间（毫秒）
  2. 客户端播放时间: audio.currentTime 是当前播放位置（秒）
  3. 字幕匹配逻辑: if (currentTimeMs >= offset && currentTimeMs < offset + duration)
  4. 延迟调整: 可通过"字幕延迟调整"参数微调，补偿网络延迟

优化建议

  • 如果字幕提前，设置正值延迟（如 +500ms）
  • 如果字幕滞后，设置负值提前（如 -500ms）
  • 音频流建议使用 HLS (m3u8) 格式，兼容性好
  • 服务端 offset 值是从 Azure 识别开始计算的，客户端需要对齐

替代方案讨论

方案2: 服务端合成音频 + 字幕 (如果方案1延迟太大)

  • 服务端使用 Azure TTS 将文本转为语音
  • 将语音和字幕打包成一个同步的流
  • 缺点: 增加服务端成本，延迟更高
